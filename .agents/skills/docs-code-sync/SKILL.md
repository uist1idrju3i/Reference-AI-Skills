# 文書と実装の照合

1. 文書の主張を、現行commitの実装・設定・試験・実行経路と照合する。過去の仕様、将来の構想、現在の実装を区別する。
2. 食い違いごとに文書の場所、根拠となるコードや試験、利用者への影響を示す。コードを正として、修正する文書と参照元、確認方法の更新計画を立てる。
3. 文書に合わせるためだけに実装を変えない。実装自体の改善が必要なら別の提案に分け、推奨案を添えてユーザーの判断を求める。
4. 承認が必要な規約変更は先に承認を得る。正本、README、利用例、コマンド、リンクを同期し、生成文書は生成元を直す。
5. 例やコマンドを対象環境で検査し、差分を再照合する。実行できない手順は未確認と記し、検査成功だけで記述全体が正しいとは判断しない。
