# 調査と検証の記録

1. 導入先の配置規約、公開範囲、既存記録を調べる。この手順の保存先は`docs/`配下のMarkdown。文書追加を禁じる規約と衝突する場合は、作成前にユーザーの判断を求める。
2. 問い、目的、対象範囲、判断基準、調査日、対象commitと未コミット差分、入力、ツール版、環境を記録する。計画と実行結果は区別する。
3. 一次資料のURL・版・参照箇所と、再実行できる手順・コマンドを残す。事実、仮説、推測、採否とその理由を分ける。
4. 成功だけでなく失敗、否定できた仮説、原データやログの所在、未実行・取得不能・未確認も残す。模擬試験と実環境、構築と実測を分ける。
5. 意味の単位で整理し、既存記録と索引をリンクする。原記録は上書きせず、訂正は由来を伴う別の記録として追えるようにする。秘密や個人環境の絶対パスを含めない。
6. 結論の有効範囲、制約、残る判断、再確認条件を明記する。記録から手順をたどれるか点検し、日本語を推敲してから保存する。
