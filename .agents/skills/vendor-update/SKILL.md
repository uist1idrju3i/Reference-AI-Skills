# 依存の追加と更新

1. 現行版・候補版・実際の利用箇所・固定方法・監視対象を調べる。Dependabotの提案も承認とは扱わず、変更範囲と完了条件を決める。
2. 公式の最新安定版を確認し、旧版から候補版まで全リリースの変更履歴と移行手順を深く読む。破壊的変更、既定値、安全性、必要な設定を実装と照合し、未読・取得不能を明示する。
3. 新機能から、この導入先で役立つものを探す。試す機能、採用・保留・不採用とその理由、互換性への影響、再確認条件を記録する。
4. 出所URL、tagとcommit、ライセンス、配布条件、帰属表示を確認する。ライセンス不明を許諾ありと推定せず、必要な判断をユーザーに求める。
5. 承認範囲で依存バージョンを更新する。外部コードは直接編集せずshallow submoduleを保つ。例として`.gitmodules`の`shallow = true`、固定タグと監視系列、lockfile、リンク、一覧表を同期する。
6. 正常系、空・不正入力、変更された契約、実際の利用経路で回帰検査する。旧版との比較で差を説明し、検査を弱めて通さない。
7. 変更履歴の対象範囲、採否、検証した版・入力・環境、失敗・未確認を報告する。上流への投稿や公開は別途許可を得る。マージは人に委ねる。
