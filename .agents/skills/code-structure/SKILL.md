# コードを責務で分ける

1. 呼び出し元、公開API、依存方向、状態の所有者、副作用、生成物と正本、既存試験を調べる。他担当の変更や実行中の処理を保全する。
2. 機能・内容・責務で境界を決める。行数だけで分割せず、関連する契約と状態をまとめる。共有化は実際に共通する責務に限定する。
3. 公開契約、失敗時の動作、互換性、移行方法を計画する。共有状態の同期、再試行・待機・資源の上限、利用者への通知やアクセシビリティも対象にする。
4. 小さな単位で変更し、追跡済みファイルの移動には`git mv`を使う。構造変更と挙動変更を分け、他担当の所有範囲は合意してから触る。生成物は正本から再生成する。
5. 正常系、空・不正入力、境界、並列実行を該当範囲で検査する。原因調査では実際に通る経路を確かめ、有力な仮説への反証も試す。
6. 公開API、例、関連文書を同じ変更で同期する。性能や見え方は対象条件で測り、ビルド成功で代用せず、未確認を報告する。
