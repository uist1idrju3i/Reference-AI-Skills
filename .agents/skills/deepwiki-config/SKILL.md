# DeepWiki 設定の設計

1. 設定を書く前にコードベースを深く調べる。入口、機能、依存、状態、設定、試験、CI、運用規約まで読み、実際の呼び出しとデータの流れを確かめる。
2. [公式仕様](https://docs.devin.ai/work-with-devin/deepwiki)を毎回再確認する。現在の上限は30ページ（Enterpriseは80）、ノート合計100件、各ノート10,000文字。契約と検査器の上限を照合する。
3. 読者の問いと実装の意味でページを設計する。`pages`は生成対象の全ページであり、少なくとも1ページ必要。役立つ範囲を漏らさず、ページ数とノート数の上限内で最大限に使う。数合わせの重複や架空の機能は足さない。
4. `.devin/wiki.json`に必須の`repo_notes`と`pages`を置く。各ページに一意で空でない`title`、具体的な`purpose`を付ける。`parent`は既存タイトルにし、循環させない。
5. `repo_notes`には全体の事実・優先順位、`page_notes`にはそのページの根拠となるコードと注意を書く。仕様案を実装済みと書かず、秘密・個人パス・重複説明を入れない。
6. ページ数・ノート数・文字数、必須項目、未知キー、親参照を検査し、コードとの対応を通読する。例として`check-wiki.py --max-pages 80`はEnterprise向けの上限確認に使う。未使用の余裕とその理由も説明する。
7. 設定のcommitとWikiの再生成を区別する。再生成に必要な操作・承認を確認し、実際の生成結果と更新状態を確認するまで「Wiki更新済み」と報告しない。
