# 文書を意味で分ける

1. 既存文書の目的、読者、主題、根拠、公開範囲、配置規約を調べる。単一文書を維持する規約があれば、新しいファイルを増やさず節で整理する。
2. 読者が答えを探す問いと情報の意味・内容で分ける。行数や容量だけで分割せず、条件・結論・証拠を切り離さない。
3. 情報ごとに正本を一つ決める。現行方針と過去の検討・実験記録を区別し、履歴を後知恵で書き換えない。公開用と内部用の資料を混ぜない。
4. 移動前に配置と索引、旧リンクの扱いを計画する。追跡済みファイルは`git mv`で動かし、移動と内容変更を区別できる差分にする。
5. 索引、相対リンク、見出しへのリンク、コード例、参照元を同時に直す。個人環境のパスや秘密を根拠に使わない。
6. 読み手の順序で通読し、重複・欠落・矛盾とリンク切れを検査する。日本語はyomiyasuで意味、条件、否定を保って推敲し、未確認を報告する。
