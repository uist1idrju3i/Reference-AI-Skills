# 判断を求める

1. コード、設定、既存の決定、一次資料で分かることを先に調べる。調査結果と仮定を分け、取得不能を明記する。
2. 本人にしか決められない点、矛盾、複数の解釈、改善案をまとめる。判断が必要な理由と、保留した場合に止まる作業を示す。
3. 選択肢ごとに得失、互換性、費用・リスク、変更範囲を比較する。推奨案を一つ選び、根拠と残る不確実性を添える。
4. 関連する質問をまとめ、何を決めてほしいかを具体的に尋ねる。ユーザーに見える挙動、権限、不可逆な操作を、推奨案の提示だけで承認済みにしない。
5. 回答まで判断に依存する変更を止める。回答後は決定、適用範囲、保留事項、再確認条件を既存の記録と計画へ反映し、承認範囲だけを実行する。
