# mruby/c で Ruby らしく書く

## 手順

1. 契約を先に決める。意図、入力、出力、空・未設定の扱い、失敗時の結果、副作用を明記します。実装の都合ではなく利用者の語彙で API を設計します。
2. 名前をそろえる。変数・method は snake_case、class/module は CamelCase、定数は SCREAMING_SNAKE_CASE。問い合わせは `?`、安全な対に比べ危険な操作は `!` で示します。すべての変更操作に `!` を付けません。時間や容量の単位は名前か定数に含めます。
3. 正常系を読み下せる制御にする。例外的な入力は guard clause で先に扱います。複数の条件・副作用・三項演算を1行へ詰め込みません。
4. block と iterator を意図で選ぶ。変換は `map`、選別は `select` / `reject`、副作用は `each` にします。変換結果を捨てません。提供側は `each` を持ち、後始末の責任も block の提供側に置きます。ただし `each` を定義するだけで Enumerable の全機能が得られるとは考えません。mruby/c では block を明示し、利用可能な method を可否表で確認します。
5. 資源の確保と解放を対にする。block と `ensure` で例外時も解放します。待機・再試行には回数か時間の上限を設け、busy-wait しません。待機 API は対象環境で実行確認します。
6. 通常の失敗を具体的な例外にする。独自の例外は `StandardError` から派生させます。`rescue Exception` で VM の未実装まで隠さず、必要な例外だけ捕捉します。失敗を握りつぶさず、呼出し側が判断できる結果か例外を返します。
7. 値の意味を分ける。`nil`、`false`、`0`、空 String を混同しません。`0` と空 String は真です。`||=` は `false` も置き換えるため、false を保存する cache では未設定の条件を明示します。既定の Integer は32bitで、上限を超える加算は実測で wrap しました。演算前の範囲検査を行い、byte と文字を区別します。
8. 動的機能と可視性に頼りすぎない。`method_missing`、`define_method`、class の再オープンを日常の設計に使いません。固定版の mruby/c は `private` / `protected` の外部呼出しを拒否しません。内部用の名前と文書で境界を示し、認可の境界にはしません。
9. 型をコードの外に置く。型は RBS などの別ファイルで表します。コードではクラス判定を増やすより、必要な振る舞いと入力契約を決めます。RBS 自体を mruby/c の実行時検査とは見なしません。
10. mruby/c で実行して確かめる。可否と実測済みの代替は[可否表](references/compatibility.md)を確認します。表にない機能、異なるバージョン・vm_config は probe kit を再実行します。compile の成功だけで実行成功としません。正常、空・nil、不正入力、例外時の解放を自己検査します。

## 原則

設計判断の根拠と出典は[原則](references/principles.md)を参照します。mruby のコード例を mruby/c の対応機能とは見なしません。

## 確認

- [ ] 契約と名前から、入力・戻り値・単位・失敗時・副作用が分かる。
- [ ] 正常系が読み下せ、変換結果と後始末を捨てていない。
- [ ] 空・nil・false・不正入力と、待機・再試行の上限を検査した。
- [ ] Integer の範囲、byte と文字、可視性の制約を確認した。
- [ ] 可否表の対象条件を確認し、必要な probe を compile と実行の両方で検証した。
- [ ] 代替の適用範囲を読み、CRuby と同じ意味だと無条件に仮定していない。
