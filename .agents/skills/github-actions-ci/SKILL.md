# GitHub Actions の設計と検証

1. 作成前に対象のビルド・試験・公開手順、必須検査、実行環境、既存の所要時間を調べる。公開操作の権限と承認条件を分ける。
2. Actions、runner、検査ツールの最新安定版を公式リリースと対応環境で確認する。確認日、一次資料URL、採用版、見送る理由を残し、プレビュー版と混同しない。
3. Actionsは版を示すコメント付きのfull commit SHA、取得バイナリはchecksumかdigest、Python依存はhashで固定する。権限を最小にし、checkoutは`persist-credentials: false`にする。
4. 最新版を確かめた後で高速化する。独立jobを並列にし、不要なセットアップを省く。キャッシュキーにOS・ツール版・lockfileを含め、不正なキャッシュや復元失敗でも正しく再構築できるようにする。
5. 必須検査にpathsフィルターを付けない。PRの古い実行はconcurrencyで中止し、公開・通知などの副作用は重複しないよう直列化する。timeoutと再試行回数に上限を設ける。
6. 外部入力をshellへ直接埋め込まず、信頼しない変更を特権付きで実行しない。秘密をログやキャッシュに入れない。共通ワークフローの正本と利用側を同期する。
7. actionlint、zizmor、対象の試験を実行し、CIのログと実測時間を変更前後で比較する。未実行のCIを成功扱いせず、失敗原因を解消する。最適化で検査範囲や安全条件を減らさない。
